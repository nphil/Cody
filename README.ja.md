# Cody

[English](./README.md) | [简体中文](./README.zh-CN.md) | [日本語](./README.ja.md)

Cody はコーディングエージェントのためのセルフホスト型 Web ワークスペースです——**エンジンを差し替えられる**、手元に置いておける IDE です。インターフェース（セッション閲覧、リアルタイムチャット、ファイル、Git、永続ターミナル、タスク、設定）は変わらないまま、その裏で動くコーディングエージェントはオンボーディング時に選び、いつでも入れ替えられます。[oh-my-pi（omp）](https://github.com/can1357/oh-my-pi) が最初からあらゆる機能を備えた基幹エンジンで、**Claude Code** と **Codex** は実験的エンジンとして利用できます。エージェントの進化は速いものです——Cody ならワークスペースを手放さずに中身だけを切り替えられます。

Cody は [kahme247/ompweb](https://github.com/kahme247/ompweb) のフォークです — [クレジット](#クレジット)を参照してください。

> **⚠️ 100% vibecoded（完全にコーディングエージェント製）。** このプロジェクト全体は、コーディングエージェントを動かすためにコーディングエージェント自身が構築したものです。作者の環境では動作していますが、インストールと利用は自己責任でお願いします。

## はじめに（Docker、推奨）

コンテナが Cody を実行する主な方法です。**エンジンを含まない**状態で配布されており、2 つのマウントとポート以外の設定は不要です：

```bash
docker run -d -p 30177:30177 \
  -v /path/to/appdata:/data -v /path/to/projects:/workspace \
  ghcr.io/nphil/cody:latest
```

続いて WebUI を開きます：

1. **初回起動セットアップ** — インスタンスは最初のリクエストからロックされており、唯一アクセスできるページでアカウント作成の手順が案内されます。このアカウントが管理者になります。パスワード用の環境変数は不要です。
2. **使用するコーディングエンジンを選択** — omp（推奨）、Claude Code、Codex のいずれかを選びます。Cody は永続的な `/data` の tools プレフィックスにエンジンをインストールし、イメージ更新後も残り、エンジン自体も個別に更新できます。
3. `/workspace/<your-project>` をワークスペースとして追加し、作業を始めます。

Unraid 向けには既製のテンプレートと詳しい手順が [docs/unraid.md](docs/unraid.md) にあります。イメージには日常的な開発ツール（git、`gh`、pip/venv 付きの python3、ripgrep、jq）も含まれており、任意で有効化できる **SSH アクセス** は、有効な場合そのままアクティブなエンジンの CLI に直結します — エンジンを終了すると通常のシェルに戻ります（[SSH](#コンテナへの-ssh-接続) を参照）。

### ソースから実行する（ベアメタル / 開発用）

Cody は npm には公開されていません — Docker 以外では、チェックアウトから実行します。
Node.js 22.19 以降と、`PATH` 上にあるエンジン（フル機能を使うには omp）が必要です：

```bash
git clone https://github.com/nphil/Cody && cd Cody
npm install
npm run dev            # 開発サーバー（127.0.0.1:30178）

npm run build          # プロダクションビルド…
npm start              # …127.0.0.1:30177 で提供（0.0.0.0 は start:lan）
```

## エンジン

| エンジン | ステータス | 使える機能 |
| --- | --- | --- |
| **omp**（oh-my-pi） | 基幹エンジン — すべての機能が有効 | フル機能のチャット（思考レベル、フォーク、コンパクション、ステアリング、サブエージェント）、モデル & プロバイダー、スキル、プラグイン、MCP、ネイティブ設定、アップデート |
| **Claude Code** | 実験的 | シンプルなチャット：プロンプト、ストリーミング応答、ツールの動作状況、中断。関係のない設定は自動的に非表示 |
| **Codex** | 実験的 | Claude Code と同じシンプルなチャット機能 |

- **UI からインストール・更新**: オンボーディングの選択画面と 設定 → ユーザーアカウント → エージェントエンジン から必要なときにエンジンをインストールでき、それぞれに **更新** ボタンが用意されています（omp は Updates パネルと System タブのバージョンチェック横にも「今すぐ更新」ボタンがあります）。アクティブなエンジンを更新すると稼働中のセッションが再起動され、古いバイナリのまま動き続けることはありません。
- **認証情報はエンジンごと**: Cody のターミナルで一度 `claude` または `codex login` を実行するか（状態は `/data/home` に保存されます）、コンテナに `ANTHROPIC_API_KEY` / `OPENAI_API_KEY` を設定します。omp のプロバイダーは設定画面で管理します。
- **ローカルモデルにも対応**: omp のモデルレジストリはカスタムプロバイダーを受け付け、Codex は `--oss` やカスタムの `model_provider` エンドポイントに対応し、Claude エンジンは `ANTHROPIC_BASE_URL` を尊重します。OpenAI/Anthropic 互換のゲートウェイ（vLLM、Ollama、NVIDIA Switchyard のようなルーティングプロキシなど）であれば、どのエンジンの裏にも接続できます。
- **機能フラグに応じた UI**: エンジンが対応していない機能は、壊れるのではなく非表示になります — Claude / Codex がアクティブなときは、設定は Cody 独自のタブだけに絞られ、omp 専用のコンポーザー機能は表示されなくなります。
- **エンジンの追加**: エンジンごとに 1 つのアダプターを用意します。実装すべき契約とチェックリスト（Pi、Cline、Cursor、…）は [docs/harnesses.md](docs/harnesses.md) にあります。
- 実験的エンジンは非対話的に動作し、ワークスペース内のファイル編集は自動承認されます。また、その会話履歴はセッションローカルです（サーバー再起動をまたいだ再生にはまだ対応していません）。

## ユーザーアカウント

テーマ付きのログイン画面、セルフサービスのサインアップ、写真付きのアカウントごとのプロフィール、アカウントごとのチャットセッションを備えています。最初に作成された人間のアカウントが管理者になり、管理者はアカウント一覧、ロール、サインアップポリシー（`CODY_ALLOW_SIGNUP=0` でアカウント作成を管理者のみに制限）、エンジンを管理します。パスワードはディスク上で scrypt によりハッシュ化され、ブラウザのセッションは署名付き Cookie です。`CODY_PASSWORD` を設定すると、組み込みの `cody` アカウントも有効になり、スクリプトやヘルスチェック向けの HTTP Basic 認証にも応答します。

コンテナ外では、最初のアカウントが作成されるまで認証はオフです（ローカル開発時のデフォルト）。コンテナ内では `CODY_REQUIRE_ACCOUNTS=1`（エントリポイントが設定）により、新規インスタンスは最初のリクエストから初回セットアップにロックされます。いずれの場合も通信そのものは暗号化されないため、リモートで利用する場合はリバースプロキシまたは VPN 経由の HTTPS が必要です。

## コンテナへの SSH 接続

`CODY_SSH_PASSWORD` を設定するか（あるいは公開鍵を `/data/home/.ssh/authorized_keys` に置き）、ポート `2222` をマップします — 認証情報がなければデーモンは起動しません。対話的にログインすると **アクティブなエンジンの CLI に直接入ります**。エンジンを終了しても接続は切れず、通常のシェルに戻ります（`CODY_NO_AUTO_ENGINE=1` を設定するとエンジンを介さず最初からシェルに入ります）。SSH は Web ターミナルと永続的な `/data/home` を共有するため、エンジンのサインイン状態、履歴、dotfiles は同じものが使われ、ホスト鍵もイメージ更新をまたいで保持されます。

## 機能

- **作業をすぐに再開**: ターミナル履歴やセッションパスを探し回らずに、プロジェクトごとに過去の会話を閲覧できます。
- **別の方向性を安全に試す**: 以前のメッセージから続行するか、セッションをフォークして別ルートに分岐できます。
- **サイドバーを整理**: 非アクティブなセッションはネイティブな記録を残したままアーカイブでき、不要になったら明示的に削除できます。
- **ブランチをまたいで作業**: サイドバーから Git ワークツリーを切り替えると、新しいセッションとエクスプローラーが選択したチェックアウトに追従します。
- **プロジェクトを見ながらチャット**: エージェントの作業中に、左側でファイルを閲覧し、右側でソース、ドキュメント、画像、音声、PDF をプレビューできます。
- **ワークスペースで本物のターミナルを使う**: シェルや `vim`、`lazygit`、`htop` などの TUI、各エンジンの CLI 向けに、複数の永続的な xterm セッションを利用できます。再接続、リサイズ、クリップボード、モバイル向けソフトキーにも対応しています。
- **充実したワークスペースパネル**: ファイル、Git（ステータス、差分、ステージング、コミット）、ターミナル、タスク（`.cody/tasks.json`）、アップデート、情報に加え、ワークスペースのチェックポイントや、切り離し可能な埋め込みアプリプレビューも備えています。
- **エージェントの成果をその場で確認**: アシスタントがローカル開発サーバーを起動すると、その URL が応答し次第、埋め込みプレビューが自動的に開きます。omp ではエージェントが `open_preview` ツールで明示的に開くこともできます。
- **セッション状態をひと目で把握**: コンテキスト使用量、コスト、コンパクション状態、システムプロンプトの詳細をトップバーで確認できます（内容はエンジンにより異なります）。
- **ターミナルに頼らない設定**: モデル、プロバイダー認証、omp のネイティブ制御（アドバイザー、承認、思考、コンパクション、メモリ、リトライ/フォールバック）、スキル、プラグイン、プロジェクト MCP サーバーを、エンジンが対応していればすべて設定画面から管理できます。
- **アプリ内で最新の状態を保つ**: エンジンのバージョンチェックとワンクリック更新に対応。Cody 自体はコンテナイメージの更新に伴って更新されます。
- **完了を見逃さない**: エージェント完了時のブラウザー通知や、スキルの更新確認に対応しています。
- **⌘K でどこへでもジャンプ**: セッションの切り替え、新規作成、テーマ切替ができるコマンドパレットです。
- **好みの見た目を選べる**: ライト/ダークがペアになった 10 種類のテーマファミリーを、WCAG AA 準拠のコントラストを備えたトークン駆動の UI キット上で提供。UI は英語、简体中文、日本語に対応しています。

## 設定

| 変数 | 説明 |
| --- | --- |
| `PORT` | サーバーポート（デフォルト `30177`。`-p/--port` が優先） |
| `CODY_HOSTNAME` | バインドするホスト名（デフォルト `127.0.0.1`。`-H/--hostname` が優先。コンテナでは `0.0.0.0` にバインド） |
| `CODY_PASSWORD` | 組み込みの `cody` アカウント用の任意のパスワード（ログイン画面と HTTP Basic 認証で使用） |
| `CODY_REQUIRE_ACCOUNTS` | `1` にすると、アカウントが 0 件でも認証を強制（新規インスタンスは初回セットアップのみを表示。Docker のエントリポイントが設定） |
| `CODY_ALLOW_SIGNUP` | `0` にするとログイン画面の「アカウントを作成」を非表示（管理者はその後もアカウントを追加可能） |
| `CODY_ALLOW_NO_AUTH` | `1` でコンテナのアカウントロックを無効化 — 認証を行うリバースプロキシの背後でのみ使用 |
| `CODY_SSH_PASSWORD` / `CODY_SSH_PORT` | コンテナへの SSH を有効化 / ポートを変更（デフォルト `2222`） |
| `CODY_HARNESS` | UI で選択される前のデプロイ既定エンジン（デフォルト `omp`。UI での選択が保存されていればそちらが優先） |
| `CODY_TOOLS_DIR` | UI からインストールしたエンジンの永続的なプレフィックス（デフォルト `<agent dir>/tools`） |
| `CODY_OMP_BIN` / `CODY_CLAUDE_BIN` / `CODY_CODEX_BIN` | 各エンジンのバイナリを指す絶対パスの上書き設定 |
| `CODY_ACCOUNTS_DIR` | ユーザーアカウントの保存先（デフォルト `<agent dir>/cody-accounts`） |
| `PI_CODING_AGENT_DIR` | インスタンスのデータディレクトリ（デフォルト `~/.omp/agent`。コンテナでは `/data/agent`） |
| `CODY_NO_OPEN` | `1`/`true` を設定するとブラウザの自動起動をスキップ |
| `HTTP_PROXY` / `HTTPS_PROXY` / `NO_PROXY` | サーバーサイドリクエスト用の標準プロキシ変数 |

すべての `CODY_` 変数は、フォーク前の `OMP_WEB_` という綴りでも指定できるため、既存の ompweb の設定はアップグレード後もそのまま動作します。ブラウザ側の設定も、初回読み込み時に ompweb のストレージキーから移行されます。

## セキュリティに関する注意

- ベアメタルの Cody はデフォルトで `127.0.0.1` にバインドします。ループバック以外への公開は、信頼できるネットワーク向けの明示的なオプトインです。Cody を HTTPS なしでインターネットに公開するのは安全ではありません。
- Web の境界防御: 未認証のページは `/login` にリダイレクトされ、API は 401 を返し、ターミナルの WebSocket も同じ認証情報と同一オリジンでのアップグレードを要求します。
- ファイル API は、選択したワークスペース、その有効な Git ワークツリー、セッションが参照するディレクトリ、明示的に選択したルートのみを許可リストとして扱います。パスはディレクトリトラバーサルやシンボリックリンクによる脱出を防ぐため正規化されます。
- ブラウザターミナル（および有効化した場合の SSH）は、コンテナのユーザーとして `/data` と `/workspace` に完全にアクセスできる状態で実行されます — これらのマウントの範囲は意図を持って設定してください。
- 実験的エンジンは、ターン実行中はワークスペース内のファイル編集を自動的に承認します。

## アーキテクチャ

Cody は Node 上でホストされる Next.js アプリで、インストール済みのエンジンバイナリを操作します — エージェント自体は同梱していません:

- **エンジンの接続点**（`lib/harness/`）: エンジンごとに 1 つのアダプター — 識別情報、機能フラグ、バイナリの検出、インストール仕様、ライブセッションのファクトリーを持ちます。実行時に選択したエンジンはインスタンスのデータディレクトリに永続化され、機能フラグがエンジン固有のあらゆる UI 要素を制御します。
- **omp セッション**: アクティブなセッションごとに `omp --mode rpc-ui`（stdio 上の NDJSON）を子プロセスとして起動し、可能な場合は RPC v2 と、上限付きのチャンク再構成をネゴシエートします。セッション履歴は omp のネイティブな JSONL を直接読み込み、ライブの書き込みと競合しないようにタイトル変更・アーカイブ・削除を行います。
- **Claude Code / Codex セッション**: ターンごとに 1 つの CLI プロセス（`claude -p --output-format stream-json` / `codex exec --json`）を起動し、サーバー側で UI が描画するのと同じイベントストリームに変換します。中断はそのターンを終了させ、再開にはエンジンのネイティブなセッション ID を使用します。
- **エンジンのインストール/更新**: ランタイムが最初に解決する永続的なプレフィックスに対して npm を実行します — インストールと更新は同じ操作であり、アクティブなエンジンを更新すると稼働中のセッションが再起動されます。
- **omp の設定面**: モデル/`models.yml`、許可リスト化された `config.yml` の設定、スキルの検出、`omp plugin`、プロジェクトの MCP サーバー（`.omp/mcp.json`）— いずれも omp バイナリまたはそのネイティブファイルを通じて行われ、すべて機能フラグで制御されます。
- **ターミナル**: カスタムの Node ランチャーが、Next.js と同一オリジンのターミナル WebSocket を 1 つのポートで提供します。各タブはサーバー側の `node-pty` シェルを専有し、ブラウザが切断されても存続します。
- **アカウント**: JSON ストアと scrypt ハッシュを、その他のインスタンス状態と並べて保存します。セッションのプライバシーは、セッション ID をキーにした所有権サイドカーによって、エンジンに依存せず保たれます。

## 開発

```bash
npm install
npm run dev
```

ローカル開発サーバーは [http://127.0.0.1:30178](http://127.0.0.1:30178) で動作します。

よく使うチェック:

```bash
npm run typecheck      # 型チェック
npm run lint           # ESLint（警告ゼロを強制）
npm test               # テストスイートを実行
npm run build          # 本番ビルド
```

ローカル開発中は `next build` / `npm run build` の実行を避けてください。`.next/` への書き込みが行われ、開発サーバーに干渉することがあります。ビルドはリリース作業のときだけにしてください。

## 国際化

Cody は英語、簡体字中国語（简体中文）、日本語をサポートしており、3 言語すべてで UI 文字列が翻訳されています。言語は `navigator.language` から自動検出され、設定画面から実行時に切り替えられます。選択内容はセッションをまたいで保持されます。

- 辞書ファイル: `lib/i18n/locales/{en,zh-CN,ja}.json`
- フレームワーク: `lib/i18n/index.tsx` — `useSyncExternalStore` をベースにした軽量なストアで、`{var}` 補間と複数形サポート（`.one`/`.other`）に対応
- API のエラーメッセージは、安定したエラーコード（`errors.<code>`）を通じてクライアント側で翻訳されます

## 品質

- **アクセシビリティ**: WCAG AA 準拠 — Lighthouse アクセシビリティスコア 100/100、全面的なキーボードナビゲーション、フォーカス可視リング、ARIA ロール
- **パフォーマンス**: リストコンポーネントの memo 化、RAF で制御されたスクロール/マウスハンドラ、デバウンス検索、ストリーミング JSONL リーダー、ETag キャッシュによるセッション一覧
- **堅牢性**: 起動したエンジンプロセスのグレースフルシャットダウン（プロセスグループ単位の kill）、エラーバウンダリ、アトミックな状態ファイルの書き換え
- **テスト**: セッション解析、認証システム、エンジンの接続点とストリーム変換、ターミナル入力、Markdown レンダリング、ネイティブ設定、MCP 設定をカバーする 450 件以上のテスト。イメージを公開する前には、CI がコンテナの初回起動フロー全体（ロックされた起動 → 管理者のサインアップ → アプリ内でのエンジンインストール）をスモークテストします。
